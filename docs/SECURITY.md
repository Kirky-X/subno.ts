## 🛡️ 安全设计

SecureNotify 采用**纵深防御**安全架构，在多个层面实施安全控制：

### 传输层安全

| 控制项       | 实现            | 说明                     |
| ------------ | --------------- | ------------------------ |
| **TLS 1.3**  | Vercel 边缘网络 | 全站 HTTPS，自动证书管理 |
| **HSTS**     | 响应头          | 强制 HTTPS 连接          |
| **证书固定** | Vercel 平台     | 自动处理                 |

### 应用层安全

| 控制项           | 实现               | 说明                     |
| ---------------- | ------------------ | ------------------------ |
| **API 密钥认证** | `X-API-Key` 请求头 | 所有 API 端点强制认证    |
| **权限分级**     | read/write/admin   | 细粒度访问控制           |
| **请求限流**     | Redis 计数器       | IP + User-Agent 双重限流 |
| **输入验证**     | Zod Schema         | 严格类型校验             |
| **端到端加密**   | RSA + AES-256-GCM  | 消息内容加密             |

### 数据安全

| 控制项           | 实现         | 说明               |
| ---------------- | ------------ | ------------------ |
| **密钥哈希存储** | SHA-256      | API 密钥不存明文   |
| **敏感数据加密** | AES-256-GCM  | 消息内容加密存储   |
| **密钥过期**     | TTL 自动清理 | 过期密钥自动删除   |
| **审计日志**     | 全操作记录   | 可追溯所有关键操作 |

### 基础设施安全

| 控制项           | 实现             | 说明                        |
| ---------------- | ---------------- | --------------------------- |
| **安全响应头**   | `vercel.json`    | `X-Content-Type-Options` 等 |
| **CORS**         | `cors.config.ts` | 严格跨域控制                |
| **SQL 注入防护** | Drizzle ORM      | 参数化查询                  |
| **XSS 防护**     | React 自动转义   | 输出编码                    |

## 🔐 安全最佳实践

### API 密钥管理

```typescript
// 推荐：定期轮换 API 密钥
// 1. 创建新密钥
const newKey = await createApiKey({ name: 'app-key-v2', permissions: ['read', 'write'] });

// 2. 迁移应用到新密钥
// 3. 验证新密钥工作正常
// 4. 撤销旧密钥
await revokeApiKey(oldKeyId);
```

**最佳实践：**

- ✅ 为每个应用/服务创建独立的 API 密钥
- ✅ 设置合理的过期时间
- ✅ 定期轮换密钥（建议每 90 天）
- ✅ 监控密钥使用情况，及时发现异常
- ❌ 不要使用永不过期的密钥
- ❌ 不要在代码中硬编码 API 密钥

### 消息加密

```typescript
// 推荐：使用端到端加密
// 1. 客户端生成密钥对
// 2. 注册公钥到 SecureNotify
// 3. 使用公钥加密消息
// 4. 发送加密消息到 SecureNotify
// 5. 接收者使用私钥解密
```

**最佳实践：**

- ✅ 敏感消息始终使用 `encrypted: true`
- ✅ 定期轮换加密密钥
- ✅ 使用强加密算法（RSA-4096 或 ECC-SECP256K1）
- ❌ 不要发送明文敏感信息

### 频道安全

```typescript
// 推荐：根据敏感程度选择频道类型
const channelConfig = {
  // 公开信息
  announcements: { type: 'public' },

  // 敏感但需要分享
  teamUpdates: { type: 'encrypted' },

  // 高度敏感
  financialAlerts: { type: 'encrypted', expiresIn: 3600 },
};
```

## 🚨 漏洞处理流程

### 报告安全漏洞

**请勿通过公开 issue 报告安全漏洞。**

请使用以下私密披露渠道：

| 渠道                           | 链接                                                                         |
| ------------------------------ | ---------------------------------------------------------------------------- |
| **GitHub Security Advisories** | [创建私密报告](https://github.com/your-org/subno.ts/security/advisories/new) |

**报告应包含：**

1. **漏洞描述**：清晰描述漏洞类型与影响
2. **复现步骤**：详细的复现步骤或 PoC 代码
3. **潜在影响**：评估漏洞可能造成的危害
4. **修复建议**（可选）：如有修复方案请提供

### 响应时间线

| 阶段         |  时间承诺  | 说明                     |
| ------------ | :--------: | ------------------------ |
| **首次响应** | 48 小时内  | 确认收到报告，开始评估   |
| **初步评估** |   7 天内   | 确定漏洞严重性与影响范围 |
| **修复开发** |  视复杂度  | 开发并测试修复方案       |
| **修复发布** |  视复杂度  | 发布安全更新             |
| **公开披露** | 修复发布后 | 发布安全公告             |

### 严重性评级

|   等级   | 描述                               | 示例                   |
| :------: | ---------------------------------- | ---------------------- |
| **严重** | 可导致系统完全控制或大规模数据泄露 | 远程代码执行、SQL 注入 |
| **高危** | 可导致敏感数据泄露或权限提升       | 认证绕过、敏感信息泄露 |
| **中危** | 可导致有限的数据泄露或功能滥用     | CSRF、XSS              |
| **低危** | 影响较小，但应修复                 | 安全配置不当、信息泄露 |

## ⛓️ 供应链安全

### 依赖管理

| 工具          | 用途                 | 命令                |
| ------------- | -------------------- | ------------------- |
| **npm audit** | 检查已知漏洞         | `npm run dep:audit` |
| **依赖检查**  | 检查依赖一致性       | `npm run dep:check` |
| **自动修复**  | 修复可自动修复的漏洞 | `npm run dep:fix`   |

### CI/CD 安全

| 检查项             | 工具              | 阶段       |
| ------------------ | ----------------- | ---------- |
| **代码检查**       | ESLint + Prettier | pre-commit |
| **类型检查**       | TypeScript        | pre-commit |
| **单元测试**       | Vitest            | CI         |
| **覆盖率**         | Vitest Coverage   | CI         |
| **依赖审计**       | npm audit         | CI         |
| **部署后冒烟测试** | GitHub Actions    | 部署后     |

### 已知依赖风险

| 依赖        | 风险       | 缓解措施                  |
| ----------- | ---------- | ------------------------- |
| `crypto-js` | 已停止维护 | 计划迁移至 Web Crypto API |
| `pg`        | 连接池耗尽 | 配置最大连接数与超时      |
